# Build a Skills & Prompts Explorer

Build a self-contained, dependency-light static explorer for the **current
repository** under `docs/explorer/`. Read real files and cite them; never invent
metadata, workflow steps, or commentary. No runtime dependencies — the only
third-party asset is the vendored markdown renderer in the kit.

The engine is repo-agnostic; only **discovery** and **curated content** are
per-repo. The static engine is bundled with this skill in
`${CLAUDE_PLUGIN_ROOT}/skills/build-explorer/kit/`. The authoring contract is
`reference/AUTHORING.md`. A clean discovery skeleton is in
`templates/build_explorer.skeleton.py`; a full worked example (a 13-plugin
marketplace) is in `examples/claude-for-legal.build_explorer.py`.

> **Golden rule:** the **mechanical manifest** (`explorer-manifest.json`,
> generated by `build_explorer.py`) and the **authored data**
> (`data/*.json` → `assets/explorer-data.js`) are separate sources, merged by
> `id` in the app. Regenerating the manifest never clobbers graphs or
> assessments.

Let `KIT = <this skill dir>/kit`, `TPL = <this skill dir>/templates`,
`REF = <this skill dir>/reference`, `DEST = <target repo>/docs/explorer`.

## Phase 0 — Detect conventions

Determine what skill/prompt conventions the repo actually uses *before* assuming
any. Skim the tree, READMEs, and config. Probe for: Claude Skills folders
(`**/SKILL.md` + frontmatter), `.claude/commands/*.md`, `.claude/agents/*.md`,
`CLAUDE.md`/`AGENTS.md`/`.cursorrules`/`.github/copilot-instructions.md`,
`prompts/` dirs and `*.prompt(.md|.yaml)`/`*.prompty`/`*.jinja`, prompt catalogs
(promptfoo/langfuse/dspy), structured registries (a TS/JSON file encoding model,
turn caps, tools, output schema, strengths/limitations), and **embedded prompts
in code** (`*_PROMPT`/`SYSTEM_PROMPT`/`*_TEMPLATE` constants, `role:"system"`
literals, `PromptTemplate`/`.from_template(...)`, triple-quoted / template-literal
prompt blocks — record path AND line range). Note what you find so coverage is
auditable.

## Phase 1 — Discover everything

1. Copy the kit into the target verbatim:
   `KIT/assets/*`, `KIT/index.html`, `KIT/serve.py`, `KIT/verify.cjs`,
   `KIT/assemble_data.py` → `DEST/` (preserving `assets/`). Copy
   `REF/AUTHORING.md` → `DEST/AUTHORING.md`.
2. Copy `TPL/build_explorer.skeleton.py` → `DEST/build_explorer.py` and
   **adapt its discovery layer** to the Phase-0 conventions (the marked `ADAPT`
   points: `EMBEDDED_FILES`, `category_for`, `parse_registry`, and any
   repo-specific `discover_*`). The skeleton already auto-detects the common
   conventions; extend it for anything unique.
3. Run `python3 DEST/build_explorer.py` and inspect the printed counts +
   coverage list. Iterate until discovery is exhaustive and deduplicated.
   Per artifact the manifest should carry: id, title, kind (skill |
   prompt-template | system-prompt | agent | subagent | managed-agent |
   slash-command | instruction-doc), category, source_path (+ line range if
   embedded), format, description, real markdown headings, and any structured
   registry/programmatic metadata (model, turn cap, tools, MCP servers,
   invocation mode, bundled resources, output schema, strengths/limitations).
   **Use a UTF-8-safe unescaper** for quoted strings pulled from source (do NOT
   use Python's `unicode_escape` — it mangles em dashes).

## Phase 2 — Author the per-artifact data

Read `REF/AUTHORING.md` first — it is the binding spec (fragment shape, graph
node rules, the `srcHeading`/`srcFocus`/`srcWhole` anchoring rules, the authored
`note` quality bar, grounding rules). Then, **by default, do full authoring**:
for every artifact author an entry in a `DEST/data/<batch>.json` fragment with

- an **assessment card** (purpose / good_at / use_when / avoid / signals /
  limits) grounded in the file's real sections, and
- a **workflow graph** of the artifact's REAL ordered process (one `start`, one
  `output`; every step/decision node anchored with an exact `srcHeading` — or
  `srcWhole` for heading-less prompts — and carrying a hand-authored 12–28-word
  `note`; `srcFocus` when siblings share a heading).

For large rosters, **fan out parallel sub-agents** — one batch per
plugin/area (≈10–14 artifacts each) — each writing one `data/*.json` fragment
and validating it with `python -m json.tool`. Give each agent `AUTHORING.md` and
the explicit artifact-id → source-path list for its batch. Every card and node
must trace to real text; spot-sample as a skeptical reader before declaring
done. (If invoked with `--manifest-only`, skip this phase — the app falls back to
faithful heading-derived "shape" diagrams and mechanical assessment fields,
provenance-labelled, so coverage never regresses to zero.)

## Phase 3 — Brand

Edit only the `window.EXPLORER_CONFIG` block (and the matching visible brand
text) in `DEST/index.html`: set `brand`, `tagline`, optional `accent` hex, and
optional `outputSchemaPath`. Replace the `YOUR_REPO` placeholders.

## Phase 4 — Assemble + verify (drive to zero failures)

```
python3 DEST/assemble_data.py     # data/*.json -> assets/explorer-data.js
node DEST/verify.cjs              # MUST exit 0
```

`verify.cjs` asserts, for ALL artifacts: graph integrity (one start/output,
valid loop/skip/stop targets), geometry (no NaN/negative sizes, chips in
bounds), section-slicing resolves node anchors to real source (curated steps may
not silently dump the whole file), every step/decision node carries an authored
summary, distinct sibling slices under shared headings, and that every
assessment + detail page renders. Also `node --check` each JS file, validate the
JSON, `py_compile` the Python, and `curl` the served site for HTTP 200. Fix
every failure; it prints the exact offending node ids. State honestly that —
without a headless browser — diagrams are validated **structurally**, not
pixel-checked; recommend `python3 DEST/serve.py` to eyeball.

## Phase 5 — Wrap up

Write/refresh `DEST/README.md`: how to serve, how to regenerate the manifest and
reassemble data, and the rules *"when an artifact's workflow changes, update its
graph"* and *"when its behaviour changes, update its assessment block."* Report
the coverage counts. Commit on a feature branch only if asked; do not open a PR
unless explicitly requested.

## Quality bar

Effort and judgement are the standard. Every user-facing string — assessment
fields AND node summaries — must be specific to *this* artifact and earn its
place; templated or "see the source" filler is a defect. Exhaustive discovery
(including embedded/in-code prompts) with a reported coverage list. Every
diagram, assessment field, and quoted excerpt traces to a file; flag
present-vs-inferred; never fabricate. Deduplicate. Works for repos with 1 or
100+ artifacts.
